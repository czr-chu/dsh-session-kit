## 关键设计决策

1. **压缩模式（P2）**：保留全部事件与工具调用结构，只做两件事——去掉流式增量（`stream`/`chunks`/`deltas` 置空）与截断超长字符串（默认单字符串 8 KiB、单事件 16 KiB，可配置）。不丢事件、不重排 `seq`，因此仍是合法 v4 日志，导入侧无需特殊处理。
2. **工作区多选导出（P3）**：面板多选工作区后，逐个调用既有 `POST /session-kit/export-workspace` 并各自下载（每个工作区一个 ZIP）；agent 工具版本接受 `workspaceIds`（≤20）并把每个 ZIP 落盘。HTTP 路由仍一次请求一个 ZIP，归档格式不变。
3. **会话迁移（P4）**：DSH 要求 `header.cwd` 解析后等于工作区路径（`dsh-workspace/src/entity.ts:139-144`），所以「迁移」= 读源日志 → 以新 id 写入目标工作区路径 → attach 到目标工作区 → 源会话移入回收站（可回滚）。源会话的子代理转录按现有策略不复制。
4. **B3 降级**：`AttachmentStore` 无删除/GC 接口（`dsh-attachment/src/index.ts`），P7 只提供只读的孤立附件报告，不做删除。
5. **顺序**：P2 打底（模式被 P3/P4 复用）→ P5（回收站，P4 依赖其 manifest）→ P4 → P3 → P6 → P7。
